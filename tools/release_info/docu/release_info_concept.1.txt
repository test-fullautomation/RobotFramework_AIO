Storage place:
--------------

RobotFramework_AIO\tools\release_info\release_info.py

Input:
------

Parameter files in JSON format, separated by distribution (BIOS/OSS)

RobotFramework_AIO\tools\release_info\release_info_config_BIOS.json
RobotFramework_AIO\tools\release_info\release_info_config_OSS.json

Content of release_info configuration files:
--------------------------------------------

Paths to other JSON files containing the concrete release information

{
   // package information provided from build process; content: framework name, version, release date
   "package_context" : "%ROBOTPYTHONPATH%/Lib/site-packages/RobotFramework_TestsuitesManagement/Config/package_context.json",

   // main and common information like highlights, hints, requirements, links; responsible: product owner
   "release_main_info" : "./release_main_info.json",

   // Release item files containing all changes made between the current and the previous release; responsible: all developers
   // Every file contains the complete history of all changes within a certain component. The goal is to inform the readers of the release mail about relevant changes.
   // This is another scope than the history in the documentation of the component. Here the information might be more technical and is related to the version number
   // of the component. The history in the documentation of the component is the history of the component. The history in the release item files is the history of changes
   // of this component between two releases of the RobotFramework AIO. Between these scopes there is not necessarily a full match.
   
   "release_items" : [
                        "..\..\..\python-extensions-collection\release_items.json",
                        "..\..\..\python-genpackagedoc\release_items.json",
                        "..\..\..\python-jsonpreprocessor\release_items.json",
                        // usw
                     ]
}

-----------------------------------

{
   "0.9.0." : [

                "requirements" : "...",
                "links"        : "..."

   "0.10.0." : [
                 "highlights"   : "...",

                 "requirements" : "...",
                 "links"        : "..."
               ]

Maybe the "links" key can also be placed outside the release numbers and appears only once within the file.


Content of release_items files:
-------------------------------

{
   "component" : "PythonExtensionsCollection",
   "releases"  : {
                   "0.9.0." : [
                                "Change 1",
                                "Change 2",
                                "Change n"
                              ], // every list element has separate row in resulting HTML output table
                   "0.10.0." : [
                                 "Change 1",
                                 "Change 2",
                                 "Change n"
                               ]
                 }
}


Execution of release_info.py creates an HTML file with all content related to the release number, defined in package_context.json.

If the command line contains an email address (optional), the HTML content is put into an email and send to this email address (usually the email of the product owner).

The product owner makes a review of the mail, adapts sender and recipients list of the mail and sends the mail to all customers.


Further possibilities:
----------------------

GenPackageDoc (and therefore also GenMainDoc) is already able to write all repository configuration values into a separate JSON file. This file is already used to add
package informations to the main documentation of RobotFramework AIO.

In case of GenMainDoc is executed before the release tool, it can be implemented that the release tool uses this information when creating the release mail. This would enable
to add informations like the the component version number and the link to the GitHub or BIOS repository to the release mail.
